How much VRAM does the KV cache need at 128K context?

Short answer: it is set by layers, KV heads and head dimension, not by parameter count. At 128K context (131,072 tokens), FP16, one sequence: Llama 3.1 8B 16.0 GiB, Qwen2.5 32B 32.0 GiB, Qwen 30B MoE 12.0 GiB, Llama 3.1 70B 40.0 GiB. Every extra concurrent sequence adds the same amount again.

Formula

bytes per token = 2 (K and V) x layers x KV heads x head dim x bytes per element
KV cache        = bytes per token x context tokens x concurrent sequences

Worked example: Qwen2.5 32B (dense, 64 layers, 8 KV heads)

2 x 64 x 8 x 128 x 2 = 262,144 bytes per token (256 KiB)
262,144 x 131,072 tokens = 34,359,738,368 bytes = 32.0 GiB

FAQ

How much VRAM does the KV cache need at 128K context?

It depends on the model's layers, KV heads and head dimension, not its parameter count. At 128K context (131,072 tokens), FP16 cache, one sequence: Llama 3.1 8B (dense, GQA) 16.0 GiB; Qwen2.5 32B (dense, 64 layers, 8 KV heads) 32.0 GiB; Qwen 30B MoE (A3B, 48 layers, 4 KV heads) 12.0 GiB; Llama 3.1 70B (dense, GQA) 40.0 GiB. Each additional concurrent sequence needs its own cache of the same size.

Why does a 30B MoE model need less KV cache than a 32B dense model?

KV cache size is 2 x layers x KV heads x head dimension x bytes per element, per token. Qwen 30B MoE (A3B, 48 layers, 4 KV heads) has 48 layers and 4 KV heads, so 98,304 bytes per token and 12.0 GiB at 128K; Qwen2.5 32B (dense, 64 layers, 8 KV heads) has 64 layers and 8 KV heads, so 262,144 bytes per token and 32.0 GiB.

Does an FP8 KV cache halve the memory?

By the formula yes: one byte per element instead of two halves the cache (16.0 GiB instead of 32.0 GiB for Qwen2.5 32B (dense, 64 layers, 8 KV heads) at 128K). This page does not measure the effect on output quality.
