Why the KV cache can still run out: reserved vs paged

A contiguous allocator reserves the maximum context for every sequence up front. A paged allocator (PagedAttention, Kwon et al., SOSP 2023) hands out fixed-size blocks on demand, so the most a sequence can waste is its last, partly filled block. That paper measured only 20.4–38.2% of KV-cache memory holding real token states in the earlier systems it evaluated; your numbers above are this workload, not that benchmark.

How it's calculated

weights = params × bytes(weight precision)
KV cache = 2 · L · T · H_kv · d_h · bytes(KV) · b  (the 2 is one K and one V per token per layer)

weights + gradients + optimizer = params × bytes/param (16 for mixed-precision Adam: 2 weights + 2 gradients + 4 FP32 master copy + 8 Adam moments; Rajbhandari et al., ZeRO, 2020)
activations per layer (16-bit) = s · b · h · (34 + 5 · a · s / h); selective = 34 · s · b · h; full = 2 · s · b · h (Korthikanti et al., 2022)
logits = s · b · V · 4 bytes (FP32)

Estimates for one GPU, no tensor or pipeline parallelism. Real frameworks add temporary buffers, so leave headroom. 1 GiB = 1,073,741,824 bytes.
